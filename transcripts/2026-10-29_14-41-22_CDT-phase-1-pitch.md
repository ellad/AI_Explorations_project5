## Agent

Both ideas are strong, interactive, and substantial enough for the assignment. Their main challenge is the same: presenting uncertain predictions responsibly rather than promising certainty.

### 1. Baking experimentation website

This could be compelling because it teaches the reasoning behind baking rather than functioning as another recipe library.

A focused interaction might be:

1. Choose a base recipe, such as chocolate-chip cookies.
2. Replace an ingredient or change its ratio.
3. See predicted effects on qualities such as spread, texture, moisture, browning, and flavor.
4. Learn why those effects are expected.
5. Optionally compare techniques such as melted versus softened butter.

The strongest feature is likely the ingredient-and-ratio experimenter. It gives beginners guidance while offering experienced bakers a creative tool.

The main feasibility concern is scientific reliability. Baking interactions are complex, so the site should present evidence-based expectations—not guarantee a precise outcome. Supporting every baked good would be too broad for five weeks. A strong MVP could focus on one category, such as cookies, and model a carefully selected group of ingredients and techniques. Additional recipe categories could become stretch goals.

### 2. Online-scam identification website

This has an especially clear audience and social purpose. A user could upload a screenshot, identify whether it came from email or text, and receive:

- A risk assessment rather than a definitive verdict
- Highlighted warning signs
- The likely scam or manipulation technique
- Safe next steps
- Reporting instructions
- General lessons that transfer to future messages

The most useful version would teach users how to evaluate suspicious communication instead of merely returning “scam” or “not a scam.”

This idea carries greater ethical and safety risk. A false “safe” result could expose someone to harm, while screenshots might contain names, phone numbers, account details, or other private information. The interface would need strong warnings, privacy protections, careful language, and a policy of never instructing users to click links or contact numbers in the suspicious message. Phone calls would also be difficult to analyze unless users provide a transcript or description.

A feasible MVP could analyze sample or pasted text first, identify common warning signs, and explain safe next steps. Screenshot recognition could be the critical technical function tested during Phase 2.

## Agent

Vite is a build tool, not a framework. During development, `npm run dev` starts a local server, usually at `http://localhost:5173`, and quickly updates the browser as code changes. When the site is ready, `npm run build` creates an optimized `dist` folder that can be published through GitHub Pages or another static host.

For Half Baked, HTML provides the page, CSS provides the visual design, and JavaScript handles recipe data, predictions, and interface interactions. Vite helps serve and package those files but does not decide how the prediction system works. Official sources consulted were the Vite Getting Started and Building for Production guides.

In plain language, the pitch can say:

> I will use HTML, CSS, and JavaScript to build the website. Vite will provide the local development server and prepare the finished files for publishing.
